DEVELOPMENT01 / FIELD NOTES

Small screens.
Thoughtful layouts.

A practical starting point for responsive interfaces: flexible grids, readable content, and breakpoints that follow the design.

Read writeup ↗
● ● ● layout.css
/* room to grow */
.grid {
  display: grid;
  gap: 1.5rem;
  grid-template-columns:
    repeat(auto-fit,
      minmax(min(100%, 18rem), 1fr));
}
FLEXIBLE BY DEFAULT.

Start with the smallest layout

Keep the first version in a single column. Set a comfortable line height, let images shrink with max-width: 100%, and avoid fixed widths on content containers. A layout that works at 320px is a useful baseline.

Let content decide the columns

CSS Grid can add columns when there is enough room. The inner min() in this example lets a card fit containers narrower than 18rem, while 1fr shares the remaining space.

.grid {
  display: grid;
  gap: 1.5rem;
  grid-template-columns:
    repeat(auto-fit, minmax(min(100%, 18rem), 1fr));
}

Check the spaces between devices

Resize slowly instead of checking only phone and desktop presets. Watch for long headings, crowded navigation, and horizontal scrolling. Add a breakpoint where the content needs it.

WEB SECURITY02 / FUNDAMENTALS

A safer way to put text on a page.

Why the way you update the DOM matters, and where textContent fits into preventing cross-site scripting.

Read writeup ↗

Keep plain text as plain text

When displaying a name, a search query, or another untrusted string, use textContent. It inserts text without asking the browser to interpret it as HTML.

const greeting = document.querySelector('#greeting');
greeting.textContent = `Hello, ${displayName}`;

Know the boundary

Assigning untrusted content to innerHTML can introduce cross-site scripting (XSS). If a feature requires rich HTML, use a maintained HTML sanitizer and a carefully chosen allowlist. Regular expressions are not a substitute for sanitization.

textContent protects this text insertion point. URL attributes, server-rendered templates, and other contexts need their own validation and encoding. A Content Security Policy can add another layer of defense.

DEVELOPMENT03 / CSS NOTES

Two themes.
One set of components.

Using CSS custom properties to make dark and light themes easier to build, maintain, and read.

Read writeup ↗

Name colors by their role

Tokens such as --surface and --text describe what a color does. Components use those tokens, and a theme changes their values in one place.

:root {
  --surface: #111114;
  --text: #f0ece8;
}
.light-mode {
  --surface: #efefec;
  --text: #111114;
}
.card {
  background: var(--surface);
  color: var(--text);
}

Test the whole interface

Switch themes while checking body text, borders, code blocks, hover states, and keyboard focus. A bright accent that works on a dark surface may need a darker value on a light surface to stay readable.

Remember a visitor’s choice where storage is available, and consider their system color preference when they have not chosen a theme yet.
